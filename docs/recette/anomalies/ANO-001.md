# Fiche d'anomalie — ANO-001

| Champ | Valeur |
|---|---|
| **Identifiant** | ANO-001 |
| **Cas de test associé** | REC-06 / REC-10 — Modification de statut d'incident |
| **Titre** | Rejet BDD lors de la mise à jour d'un incident non résolu avec date résiduelle |
| **Sévérité** | Moyenne |
| **Priorité** | Haute |
| **Statut** | **Corrigé** |
| **Date d'ouverture** | 15/10/2026 à 11:40 |
| **Date de résolution** | 15/10/2026 à 11:55 |

## Description du problème
Lors de la modification d'un incident depuis l'interface ou l'API, si le formulaire transmettait une valeur résiduelle pour `date_resolution` alors que le statut restait non résolu (`ouvert` ou `en_cours`), PostgreSQL rejetait la requête pour violation de contrainte d'intégrité.

## Erreur attendue vs obtenue
- **Attendu :** Garantir que `date_resolution` est strictement vide (`null`) pour tout incident non résolu.
- **Obtenu :** Erreur de validation en base de données provoquant un conflit lors de la mise à jour.

## Cause racine
Absence de réinitialisation/nettoyage explicite du champ `date_resolution` dans le routeur `api/routers/incidents.py` avant l'exécution de la requête de mise à jour.

## Correction apportée
Mise à jour du routeur d'incidents pour forcer le vidage du champ `date_resolution` (`None` / `null`) lorsque le nouveau statut n'est pas `resolu`.
- **Commit de correction :** `b4e912f` — *Corrige ANO-001 : forçage du vidage de date_resolution pour les incidents non résolus*
- **Test de non-régression :** Validation de la mise à jour des incidents ouverts/en_cours et contrôle de la cohérence BDD.
