## Description du problème
Lorsque le compte `direction01` tente de modifier le statut d'un incident depuis l'IHM, le système indique que l'action n'est pas autorisée, mais n'affiche pas explicitement le code d'erreur HTTP 403/422 retourné par l'API et laisse le bouton de modification visible.

## Erreur attendue vs obtenue
- **Attendu :** Masquage du bouton d'édition pour le rôle direction OU affichage clair du code HTTP et du détail (`HTTP 403: Accès réservé au rôle exploitant`).
- **Obtenu :** Message d'avertissement générique en IHM sans précision du code de réponse HTTP.

## Cause racine
Filtrage des droits bien effectif et sécurisé côté API FastAPI (HTTP 403), mais interface Streamlit non optimisée pour le rôle direction.

## Décision / Arbitrage
La sécurité back-end est respectée. Le masquage dynamique des boutons selon le rôle et la précision des codes HTTP en IHM sont **reportés au backlog V1.1**.
